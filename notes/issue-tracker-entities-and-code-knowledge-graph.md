# Issue-tracker entities as a shared code language

## Idea

Extract named entities from issue-tracker discussions—components, concepts, constraints, actors, and decisions—and map them to code. Use the mappings as a lightweight knowledge graph so the agent and user can refer to the same coherent language when discussing architecture and changes.

## Exploration

Compare direct entity-to-code links with a richer graph of entities, rationale, dependencies, and history. Test whether graph-grounded retrieval improves architectural decisions and reduces ambiguity, rather than merely adding context. See [[architectural-reasoning-for-coding-agents]] and [[issue-tracker-grounding-for-architectural-reasoning]].
